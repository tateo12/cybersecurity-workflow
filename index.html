02 / ARCHITECTURE

Findings in, tickets out

A

Ingest

Defender for Cloud via Azure Resource Graph (one query per subscription). Datadog SAST, SCA, API Security & IaC via paginated REST.

▸
B

Normalize

Every source collapses into one frozen Finding dataclass: severity, rule, target, fix, references. Sources are plugins behind a common base.

▸
C

Dedup

Stable keys derived from immutable IDs (CVE+package, rule+resource, subscription+assessment) survive title rewrites and resource renames. Searched across all projects.

▸
D

Route

Severity gate (critical/high daily, medium weekly, low logged), then ownership routing to the right team's backlog. Per-project caps stop flood days.

▸
E

File

Tickets rendered to Atlassian Document Format with fix guidance, reference links, and dedup labels. Resurfaced findings link back to the closed original.

03 / THE INTERESTING PARTS

Decisions the agent makes so humans don't have to

⤖ Cross-source dedup

If Datadog SCA and Defender both flag the same CVE on the same package, that is one ticket, not two. Dedup keys are source-agnostic where the underlying vuln is.

cve::cve-2024-21538::cross-spawn

⚖ Risk ranking inside a severity

Two Highs are not equal. A CVSS 8.9 outranks a 7.1; a Defender finding tagged "Internet exposed" + "Sensitive data" outranks "Missing patch." The agent files the scariest first.

priority_score → cvss | len(risk_factors)

⎇ Ownership routing

Container and code findings go to the platform team. VM findings go to IT ops. Identity findings and everything unrouted land with security. First match wins, each with its own assignee and epic.

routing: CYBER | AN | IT

♺ Resurfacing, not re-spamming

A finding whose ticket was closed but which shows up again gets a new ticket with a link back to the original, so regressions are visible without nagging on open work.

Resurfaced: was CYBER-217 → link-back

✂ Suppression with receipts

False positives are suppressed in version-controlled config with a reason and owner, never silently dropped. Suppression counts print in every run summary.

config/suppressions.yml

⚡ Zero secrets on disk

Locally, credentials are injected per-process from a password manager at runtime. In production they live in Function App config. Nothing in the repo, nothing in a dotfile.

op run -- python -m src.main
